Production automation — case study

Case study · Design + code

Production automation

Scripts that take the repetitive work out of design production

Some design work is really data work in disguise: the same template, filled in over and over. I write scripts that do that part, so a job that used to mean editing one file per person becomes a single run. The clearest example is the diploma generator I built for a Reiki workshop, which turns a plain list of names into a folder of finished, personalized certificates.

1 clickFrom a name list to finished PDFs
8 to 80Students per run, same effort
MinutesInstead of one file at a time
~$0Runs locally, near-zero cost

How it works

From a text file to finished diplomas

01

Data

A plain text file with the course title, date, modality and the list of student names.

02

Template

My Illustrator diploma, with the changing fields named as layers: name, title, date, modality.

03

Script

The JSX reads the file, fills each field, and shrinks a long name so it always fits the line.

04

Output

One finished, personalized PDF per student, named and saved in a dated folder.

Live demo

Try it with your name

Same rule as the real script: the name starts at 72px and shrinks, down to 60%, until it fits the line.

The engine

Real code, not a plugin

Input · datos_certificados.txt

titulo=NIVEL 1 de REIKI USUI: autotratamiento a
fecha=03/10/2026
modalidad=manera virtual en Español
alumnos:
Luna Herrera
Mora Giménez

Output · one PDF per name

generar_certificados.jsx
// Reads datos_certificados.txt and exports one PDF per student
#target illustrator

// 1 · Read the course data (title, date, modality, names)
var lineas = fDatos.read().split(/\r\n|\r|\n/);
var datos = {}, alumnos = [], enAlumnos = false;
for (var i = 0; i < lineas.length; i++) {
    var l = trim(lineas[i]);
    if (/^alumnos\s*:?\s*$/i.test(l)) { enAlumnos = true; continue; }
    if (enAlumnos) { alumnos.push(l); continue; }
    var p = l.indexOf("=");
    if (p > 0) datos[trim(l.substring(0,p)).toLowerCase()] = trim(l.substring(p+1));
}

// 2 · Fill the named layers in the Illustrator template
tTitulo.contents    = datos.titulo;
tFecha.contents     = tFecha.contents.replace(/\d{1,2}\/\d{1,2}\/\d{4}/, fechaTxt);
tModalidad.contents = datos.modalidad;

// 3 · One PDF per student — the name shrinks to fit
for (var a = 0; a < alumnos.length; a++) {
    tNombre.contents = alumnos[a];
    var tam = tamOriginal;
    while (tNombre.width > anchoMax && tam > tamOriginal * 0.6) {
        tam -= 1; tNombre.textRange.characterAttributes.size = tam;
    }
    doc.saveAs(File(salida + "/Certificado_" + slug(alumnos[a]) + ".pdf"), pdfOpt);
}
I tested Adobe's cloud data-merge and dropped it. The local script is faster, needs no uploads, and costs almost nothing to run, so making a new batch is just writing a small text file, whether it is 8 students or 80.

Why it matters

The same idea, across production

This is the thread through a lot of my work: find the repetitive part, and build the tool that removes it. The same approach powers my print-production scripts, which nest and pack images for Illustrator layouts, written in JSX and Python. It is design work that pays for itself in hours saved.
